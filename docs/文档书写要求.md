# 面向买家的FAQ文档书写要求

[English](WRITING-GUIDELINES.md) | **简体中文**

适用于本仓库首页、产品FAQ、通用排障及Windows操作指南。内部测试记录可以保留专业细节，但不能直接当作买家页的开头。新增或修改买家文档时，按本规范及[买家页模板](../product-support/DEVICE-TEMPLATE.zh-CN.md)执行。

## 1. 面向谁，怎么说

面向购买屏幕、希望尽快用起来的普通用户。像卖家在回答客户：简短、自然、直接，一句话只交代一件事。

- 用“黑屏”“画面闪烁”“左边缺了一块”“点这块却在另一块响应”等能直接观察的说法。
- 每个问题通常先给3～5个简单步骤；特殊情况再链接或展开，不把多种故障混成大段解释。
- 买家不需要先懂EDID、像素时钟、前后沿、坐标矩阵才能开始排查。
- 不写开发过程、调试流水账或与买家无关的本机状态。必要的技术解释放后面。
- 没有确认修复时直说“目前还没有已确认的修复”，不要承诺“执行后一定正常”。

| 不建议的开头 | 面向买家的说法 |
| --- | --- |
| DDC读取失败导致EDID回退 | 电脑能检测到屏幕，但仍黑屏。先检查供电和HDMI线。 |
| 触摸设备的输出映射错误 | 点小屏，却在另一块屏上操作。先核对每块屏的两根线。 |
| 水平有效窗口与坐标缩放不匹配 | 左边内容不全，而且越往左点击越不准。先试对应的补偿演示。 |

## 2. 每页固定顺序

1. **产品确认**：标题写尺寸、商品分辨率、是否触摸；一句话提醒核对订单。
2. **现象**：用买家能看到的情况做问题标题，不以协议或故障诊断做标题。
3. **先做什么**：先等待、接线、供电，再系统自带设置；不先要求运行脚本。
4. **怎么判断**：如四边完整、画面稳定、点击在本屏、触点跟随手指。
5. **没解决怎么办**：明确下一步，索取必要的照片、接线和主机信息，不让客户无限重复。
6. **可选树莓派步骤**：在基本操作之后，以可展开内容提供命令。
7. **详细原因与产品资料**：最后可展开查看参数、公式、验证证据及限制。

先写“看到了什么 → 怎么处理 → 如何判断／没解决怎么办”，最后再解释原因。步骤所需的适用条件不能藏起来，例如“仅适用触摸款”“只在测试应用内生效”。

## 3. 基本排查的优先级

### 碰到线后黑屏或闪烁

优先写：先不要动线，等约10～15秒；没恢复就重新插紧HDMI和USB供电线，两端都检查；反复碰线就出问题，优先换线。先单屏，再双屏，供电按商品要求。

等待时间是操作建议，不是保证恢复的时间。不要直接引导修改分辨率、刷固件或安装驱动。

### 触摸没反应、响应到别的屏幕

先说明：触摸款随附的USB供电／触摸线同时传数据，要接到**正在输出画面的同一台电脑或树莓派**，不能只插充电头；纯充电线不能传触摸。

双屏时每块屏的HDMI与USB成组检查，先单块测试，再接另一块。线接对仍串屏，再讲系统的对应屏幕设置。接到同一主机不保证自动解决所有串屏。非触摸款不能暗示接USB就能获得触摸。

### 画面缺边或触摸偏移

先检查实体画面是否完整、触摸是否在本屏，再判断是否需要校准或专用补偿。靶点布局参数不是校准。普通缩放、60Hz或触摸校准不能保证找回切割屏缺失的画面。

## 4. Windows和树莓派分开写

| 平台 | 买家先做什么 | 后续内容 |
| --- | --- | --- |
| Windows 10／11 | 接线；显示设置选中本屏；对应分辨率；双屏按需扩展；列表支持时尝试60Hz | 触摸串屏先用Tablet PC设置的Setup指定屏幕，确认所属屏后再考虑Reset／Calibrate；界面可用性因系统及控制器而异 |
| 树莓派 | 接线、供电、确认图形桌面已登录 | 再提供对应产品的`screen-config`、`screen-test`或演示程序，写明工具版本及系统要求 |

Windows操作链接[英文指南](../platforms/windows/README.md)／[中文指南](../platforms/windows/README.zh-CN.md)。不要把树莓派命令当作Windows操作，不写成安装同一脚本即可通用。只选择系统实际提供的分辨率和刷新率。

没有验证的平台要明确说未验证。例如6.2切割屏的树莓派应用补偿，不等于Windows整桌面已有修复。圆屏可能看不到Windows角落校准点，不让用户猜着点击。

## 5. 三类问题的写法

| 问题类别 | 必须说清楚 |
| --- | --- |
| 黑屏／闪烁 | 接线、供电、系统模式优先；只有证据支持才归因EDID／时序，不能把全部黑屏闪烁都写成EDID问题 |
| 触摸无响应／串屏／偏移 | 先USB数据线、主机和屏幕配对；再系统设置；区分单屏、同款双屏、异款双屏、触摸＋非触摸 |
| 切割屏 | 区分商品可见分辨率与输入分辨率；只有测量后才提供窗口和坐标补偿；明确应用内、系统全局、开机持久化各自是否实现 |

不适用的类别简短写明，不为填满栏目编造问题。相同控制器名、EDID或尺寸，不代表同一面板、同一固件或同一修复适用性。

## 6. 产品命名与目录

- 按“尺寸－商品分辨率－是否触摸”建产品目录；细则见[命名规范](../product-support/NAMING.md)。未知触摸属性暂用`touch-unconfirmed`，不能猜测。
- 所有首页、产品索引按英寸数**从小到大**排序，同尺寸条目相邻。
- 不将EDID输入模式直接当作玻璃的原生分辨率；切割屏特别区分商品、可见区和输入模式。
- 不因新认识改掉已发布脚本ID；说明历史名称的含义，旧目录保留跳转。
- 未取得SKU、ASIN、批次、料号时写“待确认”，不要编造。

## 7. 英文默认，中文独立

买家页默认`README.md`英文，中文为独立的`README.zh-CN.md`。顶部互相提供语言切换链接，不把完整双语段落混在同一页。

中英文的步骤顺序、参数、命令、适用条件、验证状态要一致；语言应自然，不逐字硬译。其他文件名有历史链接时保留或提供跳转。维护者规范及模板应在入口处明确身份，不伪装成客户可执行方案。

## 8. 脚本与专业内容放最后

脚本区标为“可选：树莓派操作”，可以用`<details>`折叠。必须交代：

- 适用产品、平台、工具最低版本，在哪里运行及是否需要sudo。
- 选择哪个接口：公共编号1／2对应Linux HDMI-A-1／2，板上HDMI0／1。
- 先临时验证，再考虑保存；写明会不会重启桌面、有无自动恢复及已支持的回退方法。
- 未安装工具、模式缺失或产品不匹配时怎么办；不虚构命令、参数或自动修复能力。
- 演示程序、已发布配置及全局修复必须区分。文档中的USB设备节点和路径仅作明确占位，不复制开发机映射。

技术详情最后收纳基本参数、EDID、时钟、同步值、USB标识、补偿公式、图片与验证限制。截图只证明系统输出，不能代替实体屏幕完整性及触摸准确性验证。命令成功或程序启动不等于硬件修复通过。

## 9. 证据与验收

分别标注“实物已确认”“只检查了启动／截图”“未验证”“未解决”。记录日期和适用样机；失败试验不能变成推荐方案。

一台样机成功不推广到所有批次；触摸款结果不直接套到非触摸款。新证据推翻旧判断时更新买家结论，历史事实保留在详情，不让两种说法同时误导买家。

## 10. 提交前检查

- 买家是否不懂专业名词、不运行脚本，也能先完成简单检查？
- 是否先讲现象、再给操作，必要的限制紧邻操作？
- Windows、树莓派是否明确分开？未知方案有没有承诺过头？
- 两份语言是否齐全、互链、内容一致？产品排序是否正确？
- 命令是否存在、文件链接是否有效、占位符是否清楚？
- 是否包含个人目录、真实密码、令牌、客户资料或未经脱敏的设备备份？公开文档不得包含这些信息。
- **Git commit信息使用英文**。只说明实际改动，不把文档更新描述成硬件已经修复。

说明文档通常验证内容和链接即可；附带程序需做相应语法、运行或行为检查，并如实注明未完成的实体验收。
