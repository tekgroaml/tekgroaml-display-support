# 6.2英寸360×960切割触摸屏

[English](README.md) | **简体中文**

适用于标称360×960的6.2英寸长条触摸屏。已测切割玻璃样机需要专用可见区布局。下述方案只补偿测试应用，不是整个桌面的驱动，也不修改屏幕固件。

以下命令在安装[显示工具](https://github.com/tekgroaml/tekgroaml-pi-display-tools)后的树莓派中执行，矩形触摸测试需2.3.2+。示例为接口1（`HDMI-A-1`，板上HDMI0），接口2（板上HDMI1）替换数字。测试命令使用桌面用户，不加sudo。

## 左边内容显示不全，文字、按钮或靶点被截掉

**可能看到的现象：**右边正常，左侧边框和按钮缺失，单纯修改分辨率也没解决。

可先试随文提供的补偿测试应用：

1. 安装显示工具2.3.2+并下载本支持仓库，先关闭旧临时测试窗口。
2. 在**支持仓库根目录**查看当前屏幕：

   ```bash
   screen-config list
   screen-test stop
   ```

3. 所选输出已经是**420×960、无旋转、缩放1**时执行：

   ```bash
   python3 product-support/6.2inch-360x960-touch/scripts/6.2inch-360x960-touch-window-demo.py --screen 1
   ```

4. 检查四边白框和五个编号圆点是否完整，再点击、滑动确认触摸。启动终端按Ctrl+C退出。

此前采用同一方法的临时应用已由用户确认内容完整、触摸精准；随文程序复现该方法，已检查启动和截图，新五点界面仍需单独实体验收。若程序提示输出模式不符，或边缘仍被截，请提供照片与`screen-config list`结果，不保存未经验证配置，也不继续猜分辨率。

**适用范围：**只在这个应用内补偿，普通桌面、浏览器及标准`screen-test`不会自动修正。实际应用也需要采用相同的可见区布局。

## 右侧按钮接近正确，越往左点击越偏左

先确认触摸响应在当前实体屏；若跑到另一屏，先按[配对指南](../_shared/README.zh-CN.md#二触摸无响应串屏与偏移)处理。随后运行上面的补偿演示，它同时调整显示窗口与触摸位置。

点击中心及四角，命中应变绿，白色触点应跟随手指。已在其他地方校准过的输入不能重复补偿。普通`screen-test touch --shape rect`只换靶点布局，没有切割屏补偿。

## 能显示，但画面仍然闪烁

1. 先检查屏幕额定供电和线材。
2. 支持确认该样机匹配已知触摸长条屏配置后，可临时试下面的时序修复。先保存桌面文件，配置可能重启桌面，没有倒计时恢复。

   ```bash
   screen-config apply --port 1 --profile 6.2inch-420x960-60hz-ltm-zl480 --confirm-profile
   screen-test pattern --screen 1
   ```

3. 稳定性与完整性分开检查。早期触摸样机60Hz后闪烁改善，**但并未修复左侧缺边**。

可见区与触摸成功试验使用约51.85Hz；60Hz与补偿组合仍需实体确认。不能只因画面稳定就加`--save`。

#### 一、闪烁／黑屏：时序问题单独处理

此前触摸样机在420×960、32.4MHz、精确60Hz下闪烁消失，但这只修正输入时钟，**不修正切割屏可见窗口**。后续边框测试确认左侧仍缺失，早期“60Hz后画面完整”的结论由本次结果更正。

工具2.3.0+，核对样机、接口及供电后，可临时使用现有时序档，以下以接口1为例：

```bash
screen-config list
screen-config apply --port 1 --profile 6.2inch-420x960-60hz-ltm-zl480 --confirm-profile
screen-test pattern --screen 1
```

历史配置名中的420表示输入宽度，不将商品实际宽度改成420，也不包含补偿逻辑。应用可能重启桌面，先保存文件；没有自动倒计时恢复。时序稳定、可见窗口和目标应用分别验收前，不加`--save`。DDC正常时用`screen-config auto --port 1 --save`恢复原始首选模式，但闪烁可能再次出现。

2026-11-08窗口及触摸补偿成功试验使用原始约51.85Hz输入。**60Hz＋窗口补偿＋触摸补偿的组合尚未经实体确认。**

#### 二、触摸偏移：同时处理缩放和偏移

将完整360宽画面放进可见区后，右侧靶点较接近，越向左触点越偏左；中心点击记录约X=209，而可见画面中心为X=240。

在本次无旋转、缩放1、420×960窗口中，试验公式为：

```text
屏幕X = 60 + 接收到的窗口X × 360 / 420
屏幕Y = 接收到的窗口Y
```

用户确认补偿后触摸精准。若应用使用放置在X=60的360宽逻辑画布，则逻辑坐标为：

```text
画布X = 接收到的窗口X × 360 / 420
画布Y = 接收到的窗口Y
```

公式针对桌面／窗口像素，不是直接针对0…4096原始控制器单位。已校准输入不能重复补偿。先解决触摸对应输出的问题；通用USB中转只区分名字及路由，不做坐标校准。其他控制器、旋转、缩放和输出布局要重新测量。

#### 三、切割屏显示补偿：复现已验证方法

HDMI保持420×960，将X=0…59留黑，**整个应用按360×960逻辑画布布局**，绘制时向右偏移60。不能只把420宽界面整体右移，否则右边60列又会丢失。

| 测试 | 结果 |
| --- | --- |
| 原始约51.85Hz的420×960 | 左侧缺失 |
| 60Hz的420×960 | 左侧仍裁切 |
| 60Hz、28.8MHz的360×960 | 仍裁切，右侧出现额外竖线 |
| 420×960、60Hz，水平80/20/20 | 左侧裁切位置基本不变 |
| 另一组20/20/80前后沿 | 已应用，但未留存明确用户结果，不作为有效方案 |
| 输入420宽，内容仅放X=60…419 | 用户确认内容完整 |
| 同一窗口＋X坐标缩放及偏移 | 用户确认触摸精准 |

##### 随文提供的应用演示程序

[scripts/6.2inch-360x960-touch-window-demo.py](scripts/6.2inch-360x960-touch-window-demo.py)将已验证的应用级方法整理为可复现程序。需已安装显示工具2.3.2+、其GTK依赖及运行中的labwc/Wayland桌面。此新整理文件本身不是已发布的`screen-config`配置档，也不是系统校准工具。

在本FAQ仓库根目录，通过桌面用户SSH执行，不加sudo：

```bash
screen-config list
screen-test stop
python3 product-support/6.2inch-360x960-touch/scripts/6.2inch-360x960-touch-window-demo.py --screen 1
```

所选输出须已为420×960、无旋转、缩放1。程序不改时序、EDID、USB绑定或系统校准；只把360宽测试界面放在X=60处，触摸也仅在本窗口补偿。五个靶点命中变绿，滑动可观察补偿轨迹，并检查四边白框。加`--raw-touch`可比较未校准触摸；加`--left 0 --width 420 --raw-touch`可查看完整的未补偿输入画布。默认60/360只适用于本次测量样机，不泛化到所有切割屏。

在启动程序的SSH终端按Ctrl+C退出，不安装服务或开机设置。先关闭旧临时实验窗口，否则旧覆盖层可能挡住本窗口；在旧前台终端Ctrl+C，或根据记录的PID只结束对应实验程序。

##### 已解决范围与限制

原临时程序中已确认内容完整、抽样触摸准确。尚未实现／验收：整个360宽桌面、第三方应用自动放置、桌面全局校准、开机持久化、重连、冷启动、全部边缘点、多点及其他批次。标准`screen-test touch --shape rect`只改变布局，不包含本补偿。其他应用要采用相同逻辑画布和输入变换，或另行验证桌面级方案。本应用级绕行方案不需要刷驱动板固件。
