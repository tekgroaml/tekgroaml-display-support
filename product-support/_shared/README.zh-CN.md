[English](README.md) | **简体中文**

## 先别急着改设置

- **碰线后黑屏或闪烁？**先别动线，等约10～15秒；没恢复就拔下HDMI和USB供电线重新插紧。每次碰线都发生，优先换线。
- **触摸没反应，或跑到另一屏？**触摸款的USB供电／触摸数据线要插到**正在输出画面的同一台电脑或树莓派上**，不是只插充电头。每块屏的HDMI与USB成组核对，纯充电线不能传触摸。
- **用Windows？**先看[Windows画面及触摸操作](../../platforms/windows/README.zh-CN.md)，本仓库的树莓派命令不能在Windows运行。

## 一根HDMI带两块屏，先确认输入方式

系统只识别一个逻辑显示器可以是正常现象。硬件同显板接收一张图再复制；SBS板接收双宽图并左右分区。此次记录中同显输入为480×480，异显输入为960×480，但不能据此推断所有双屏产品相同。[按产品样本查看](../_unconfirmed/README.zh-CN.md)，其中尺寸和触摸选项仍待确认。

一块不亮先检查接线、电源和驱动板；不要因截图两区完整就认定实物没有故障。换板后演示停止时，先核对当前输入与对应布局，不用其他产品的时序修复档，也不强制60Hz。

## 双屏同显与异显：场景和画面分配

**本系列一根HDMI带两屏：同显时两屏重复完整画面；异显时应用先准备左右两页，再分别显示到两屏。** 同显适合重复信息／对称装饰，异显适合仪表／主辅看板。这里“镜像”表示正常方向的画面复制，不是文字左右翻转。

[查看圆形／方形应用场景、驱动板流向图与演示入口](dual-screen/README.zh-CN.md)。一根HDMI在系统里只显示一个编号可以是正常的；同显板的单幅输入与SBS板的双宽输入不能直接混用。

## 一、黑屏、闪烁与EDID读取错误

4.0英寸方屏及早期6.2触摸样机确有EDID／时序问题，但**不能把所有黑屏闪烁都归因于EDID**。非触摸长条屏亮度闪动、2.8英寸黑屏仍未解决。

1. 核对型号、额定电源、背光、接口，先单屏与已知良好的线材对照。树莓派欠压标记不测量屏幕端电压。
2. 检查连接、启用状态、模式、EDID覆盖与模式列表：

   ```bash
   screen-config list
   screen-config modes --port 1
   ```

3. 仅选择匹配产品的已上报模式。`set`不生成缺失模式；`auto`验证EDID后选上报首选模式，错误EDID可能仍选错。
4. 专用档只用于已核对控制器／时序。ZL480名称、EDID毫米尺寸、序列字符串均不能确认玻璃尺寸、SKU或芯片型号。
5. 检查实体，不只看命令成功或截图：

   ```bash
   screen-test white --screen 1
   screen-test pattern --screen 1
   screen-test cycle --screen 1 --interval 5
   screen-test stop
   ```

白色检查发光；网格检查边框及几何；循环为黑白红。四边、稳定性实际通过后才保存。普通配置命令多无自动倒计时恢复，并可能重启桌面；先保存图形文件并保持SSH。

`[Errno 121] Remote I/O error`曾在直接读取EDID／DDC时复现。HDMI检测为connected仍可能读不到EDID。检查屏幕供电、HDMI接触、转接线及其他主机。回退1024×768不代表面板就是该分辨率，不用任意EDID掩盖读取故障；DDC失败时`auto --save`不能保证恢复。

系统截图完整而实体缺边时，重点查后级裁切及显示窗口；截图无法直接测出玻璃可见范围。符合实测窗口的切割屏按对应产品方案处理。

## 二、触摸无响应、串屏与偏移

| 症状 | 处理及记录 |
| --- | --- |
| HDMI有画面但不能触摸 | 检查USB数据线及正确触摸口；纯供电线没有触摸数据 |
| 点击无可见反馈 | `cycle`是定时颜色测试，不验证触摸；`touch`才显示靶点和轨迹。测试程序后补鼠标／模拟鼠标支持，因部分环境未送达原生触摸；验证时只用手指区分真实鼠标 |
| 两块触摸都控制同一屏 | 相同或不同型号均可能使用同名、无唯一序列号的控制器；逐屏点击识别后按USB路径分别映射，调试已确认修复 |
| 恰好互相反屏 | 交换两个已确认原始设备参数，重新配置并验收；一次初始绑定反了，交换后通过 |
| 一块触摸＋一块非触摸 | 唯一控制器仅绑定所属输出，已确认修复；两设备配置脚本不能用于只有一个控制器的情况 |
| 本屏响应但位置错 | 先查旋转、缩放、旧校准及画面与玻璃对齐，再校准 |
| 切割长条右侧接近、左侧误差大 | 显示窗口与触摸缩放一起补偿，单纯平移不足 |
| 无触摸硬件但要显示靶点 | 仍可显示测试图，缺少触摸不会抑制视频输出 |

### 屏上测试

```bash
screen-test touch --screen 1 --shape rect
screen-test touch --screen 2 --shape round
screen-test tap-cycle --screen 1
screen-test status
screen-test stop
```

`rect`为中心＋四角，`round`为中心＋上下左右；布局不校准输入。`tap-cycle`新按下时黑→白→红，长按／拖动不连续切换，双屏分别变化。坐标检查用靶点及轨迹；5/5只是五点抽样，不代表全屏校准或多点能力验收。

### 确认两组USB／HDMI配对

1. 只点实体1号屏记录对应原始控制器，再识别2号屏；不能用event编号、USB路径数字或枚举顺序猜测。中转服务独占已配置原始设备，此时监测原始节点可能无事件；观察对应虚拟节点，或受控识别期间明确停止中转。
2. 安装`python3-evdev`后，在显示工具源码目录使用已确认的原始节点。`eventN`、`eventM`、`YOUR_DESKTOP_USER`都是占位符，不能原样复制：

   ```bash
   sudo python3 scripts/configure-touch-map.py \
     --screen1-device /dev/input/eventN \
     --screen2-device /dev/input/eventM \
     --user YOUR_DESKTOP_USER
   ```

3. 程序保存USB路径到`/etc/pi-setting/touch-map.json`，生成不同虚拟设备名及labwc映射，启用`pi-setting-touch.service`；2.3.1+还通过udev创建`/dev/input/USB-TOUCH-1/2`。内部兼容名`PiSetting Touch HDMI0/1`对应公共输出1/2，不改变客户编号。
4. 桌面用户SSH中先确认该用户只有一个labwc会话，才能使用以下重载方式：

   ```bash
   pgrep -a -u "$(id -u)" -x labwc
   pkill -HUP -u "$(id -u)" -x labwc
   screen-test touch
   ```

   多会话时只向已核对PID发信号。用`systemctl status pi-setting-touch.service`及`journalctl -b -u pi-setting-touch.service --no-pager`检查服务与日志。
5. 视频线和USB线成组贴标签，固定树莓派USB插口／集线器拓扑。USB路径1.1不天然等于HDMI1。换插口、集线器、控制器或屏幕归属后重新识别。配对与命名可持久化；切割屏坐标补偿是另一项应用内试验。

配置程序备份旧映射及labwc配置，新版还备份命名规则。回退时恢复同组备份、重启中转并重载labwc；标签变动时同时恢复并重载udev。`sudo systemctl disable --now pi-setting-touch.service`会释放原始设备，但旧通用配置可能再次串屏。不复制其他客户机器的路径。

## 三、热插拔、退出桌面或SSH重连后测试界面不出现

曾出现状态显示touch运行、无错误，但截图仅桌面的情况。重启测试进程后网格恢复：

```bash
screen-test stop
screen-test pattern --screen 1
```

这是该会话已验证的恢复步骤，未发布自动热插拔修复。非触摸屏也能显示图案／靶点。没有Wayland会话时先登录图形桌面，SSH登录本身不启动桌面；重启显示管理器会关闭图形应用，不作为首选通用操作。SSH的`Broken pipe`仅说明远程连接丢失，网络、供电及重启要独立排查；保活只能减少空闲断线，不能修复显示硬件。

## 四、双屏套装换板后演示停止或模式被拒绝

2026-11-01确认过这些不同输入：SBS双480输入960×480@约62.825Hz；硬件同显输入480×480@约62.811Hz，另一次圆形同显板约71.295Hz。不要把两次连接当同一SKU，不从EDID“DELL U2410”等名称推断尺寸或生产商。

这些约62.811／71.295Hz的后续兼容改动发生在独立[应用仓库](https://github.com/tekgroaml/lvgl-embedded-gui-demos)的布局接受范围，没有修改HDMI时序或屏幕固件，也没有新增对应`screen-config apply`配置。应用v0.10.2已含四类脚本。安装或升级须按上游说明停止旧版、复制完整项目；SSH中以已登录桌面的普通用户运行，不加sudo。

| 显示关系／形状 | 对应脚本 | 记录所用输入 |
| --- | --- | --- |
| 同显圆形 | ./demos/same/round/demo | 480×480 clone，实际约62.811或71.295Hz |
| 同显方形 | ./demos/same/square/demo | 480×480 clone，实际约62.811Hz |
| 异显圆形 | ./demos/different/round/demo | 960×480 SBS，实际约62.825Hz |
| 异显方形 | ./demos/different/square/demo | 960×480 SBS，实际约62.825Hz |

完整命令、产品边界及实物验证状态见[四个样本条目](../_unconfirmed/README.zh-CN.md)。同显脚本默认clone，显式`--signal sbs`才选择双宽软件同显；方形同显SBS布局并未接受约62.825Hz，不能把同形状异显的接受范围直接套过去。

重新连接后，应用可能因断开或模式变更已退出。确认供电／图形桌面及识别正常，停止旧实例，再用对应脚本check/start；不要默认原进程会自动恢复。保持SSH并正常stop可退出应用；这些命令不改时序、无倒计时回退，也不回退其他工具的系统设置。旧脚本路径仅转发，不能替代完整升级。

所有演示是模拟数据、无声。没有触摸操作不证明产品无触摸；Pi4B没有板载喇叭，系统“Built-in Audio”只表示输出设备，不证明屏幕带音箱。特定HDMI声音测试失败未建立原因，不作为屏幕无音箱或坏了的结论。
