# 圆形双屏同显套装，480×480输入；非触摸，尺寸待确认

[English](README.md) | **简体中文**

这是待核实的连接样本条目，不是已确定的商品型号。本套装已确认不带触摸，请核对订单及每屏尺寸；480×480来自布局／输入记录，商品标称和面板原生规格尚未建立。不要仅凭分辨率把它当作现有2.8英寸款。

## 换屏后能看到桌面，但演示停止或提示模式不匹配

硬件同显板需要一张方形图像，不是SBS异显板的双宽图像。换一块板后，上报刷新率也可能不同。

1. 先别动线，等约10～15秒；没恢复就重新插紧主机和驱动板两端的HDMI、USB供电。按商品额定要求供电，不在通电时插拔面板排线。
2. 核对驱动板是一根HDMI带两个面板，以及是同显还是左右异显。不能仅因有两块屏就假设主机会识别两个显示器。
3. 在Windows先用[系统显示设置](../../../platforms/windows/README.zh-CN.md)查看实际提供的分辨率；在树莓派先确认图形桌面已登录。同显板与SBS板的完整输入不同，见后文。
4. 两块实体圆屏应显示相同的完整画面，频谱、光效或时钟持续变化。应用运行正常仍不能证明两块实体都收到画面。

仍异常时，请提供两块屏同时入镜的照片、背光是否亮、主机／系统、供电规格、HDMI与USB接线及驱动板标签。不要连续尝试其他产品的修复档；尚未确定具体故障时不承诺软件能修好。

## Windows中只有一个显示器编号，是否少识别了一块？

一根HDMI驱动两个面板时，主机只看到一个逻辑输出可以是正常现象。Windows的“复制／扩展”针对主机输出，不能自动改变驱动板内部的同显或左右分区。不要把本仓库Pi程序当Windows驱动；这套双屏板在Windows的完整产品验收未完成。

## 触摸无响应，或图案边缘缺失

卖家已确认：本双屏套装**不带触摸**。点击任一面板没有反应是正常现象，不需要触摸校准或USB触摸映射脚本，USB供电不会增加触摸功能。2.1英寸和2.8英寸单屏系列另有触摸型号，应按订单区分。

本款没有已测切割窗口，不套用6.2英寸的60列补偿。先核对输入、形状和内容布局；圆屏四角隐藏不等于切割故障。

## 可选：树莓派检查与演示

<details>
<summary>展开Pi命令（不适用于Windows）</summary>

适用Pi4B、Bookworm Desktop 64位、labwc/Wayland。只读识别命令来自另装的2.3.2+版[显示工具](https://github.com/tekgroaml/tekgroaml-pi-display-tools)；缺少命令先按该项目安装，不尝试其他档。应用演示来自独立的[双屏应用仓库](https://github.com/tekgroaml/lvgl-embedded-gui-demos)，本页统一使用**v0.10.2或后续兼容版**，避免旧布局未接受已记录速率。

先检查，不改模式：

```bash
screen-config list
screen-config modes --port 1
```

本记录完整输入为**480×480、约71.294998Hz**；其他批次需核对实际上报，不能强制复制此数值。公共接口1/2=Linux HDMI-A-1/2=Pi4板标HDMI0/1，不是两个实体面板的左右编号。接口2接线时把命令中的1换2。

使用完整应用仓库的安装说明；旧版若正在运行，先用旧版正常stop，再更新完整目录，不能覆盖运行中的程序。`screen-config`与`./app`属于不同项目。

在Pi已登录桌面的同一普通用户SSH中、应用根目录执行，不加sudo：

```bash
cd ~/apps/lvgl-embedded-gui-demos
./app --version
# 停止本项目原场景；其他项目占用时用其自身正常stop命令
./app stop --port 1
./demos/same/round/demo check --port 1 --signal clone
./demos/same/round/demo start --port 1 --signal clone
```

若安装了screen-test且占口，先用它的`screen-test stop --screen 1`，再检查应用。演示为**音乐律动→RGB氛围→桌面信息钟**，每组品牌与场景介绍3秒、效果10秒，一轮39秒；不是EDID修复、驱动安装或桌面全局补偿。

稍后查看／结束：

```bash
./demos/same/round/demo status --port 1
./demos/same/round/demo logs --port 1 --follow
./demos/same/round/demo stop --port 1
```

这些app命令保留已有输入信号，不重启桌面、不刷固件，不提供定时回退；失败时不会自动生成缺失模式。start后台运行，SSH退出后继续，前提是桌面保持登录。换板、拔线或模式改变后程序可能退出，重连稳定后重新check/start，不能指望旧进程自动恢复。停止演示只能关闭本项目窗口，不回退之前由其他工具改过的系统设置。

`check`若报告宽高／速率不匹配，先核对该板是clone还是SBS、实际输出与应用版本，不为通过检查强制设60Hz或刷任意EDID。若无唯一Wayland会话，先登录图形桌面；`running/ok`只代表运行检查，须观察两块实体屏。

### 已确认什么

较早连接曾记录480×480、62.811001Hz；2026-11-01后一次圆屏连接的首选／当前模式为480×480、71.294998Hz。两次板卡／批次对应关系未确认。v0.10.2接受后一次上报信号并启动圆形同显，帧数递增、状态running/ok；未取得独立的实体两屏验收反馈。

### 没有确认什么

尺寸、商品分辨率、真实控制芯片／PCB修订、Windows、冷启动、睡眠唤醒、长期稳定性和其他批次没有建立完整验收。未记录的完整同步时序不补猜；相同EDID名称和刷新率不能证明同一产品。无专属`screen-config apply --profile`修复档，也没有新建假定尺寸的修复脚本。

应用通过识别布局而出图，不表示屏幕时序已被修正。此次问题不能泛化成“所有屏都应强制60Hz”或“更新程序一定能修好黑屏”。
