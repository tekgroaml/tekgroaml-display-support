# HDMI 触摸屏：客户常见问题

适用范围：使用HDMI传输画面、使用USB传输触摸数据的屏幕。不同产品的供电和接口可能不同，请以购买型号的接线图为准。以下操作不会要求提供Wi-Fi密码、电脑密码或远程登录密码。

## 先做这四项检查

1. 确认屏幕已有稳定画面。若黑屏、无信号或严重闪烁，先处理显示和供电问题。
2. HDMI线连接主机与屏幕；触摸USB数据口也要连接到**同一台主机**的USB口。
3. USB线必须支持数据传输。触摸口只接充电器，无法将触摸信息传给电脑或树莓派。
4. 多屏出现问题时，先只连接一块屏幕，分别验证每块屏幕，再逐一接回。

## Q1：屏幕有画面，为什么点击没有反应？

画面和触摸通过不同连接传输。有画面只能说明视频连接可用，不能证明触摸USB已连接。

请确认插的是屏幕用于触摸的USB口；如果有多个USB口，不要只根据插头形状判断。换一条确定可以传数据的线，直接接主机USB口，先绕开USB集线器、延长线和扩展坞测试。屏幕按说明书供电，不要尝试未标注的电压。

## Q2：USB已经接上了，为什么仍不能触摸？

需要区分三种情况：

| 现象 | 下一步 |
| --- | --- |
| 系统根本没有识别到触摸设备 | 检查数据线、正确接口、USB口和供电 |
| 系统识别到设备，但操作无反应 | 检查应用是否接受触摸、桌面是否登录，以及触摸是否落在另一块屏幕 |
| 触摸有反应，但点错位置 | 先确认映射到正确屏幕，再处理旋转或坐标校准 |

不要因为有画面就反复修改分辨率，也不要在没有识别到USB设备时先安装来历不明的驱动。

## Q3：如何直接看到点击和滑动是否正常？

如果卖家已提供并安装适用的树莓派`pi-setting`工具，可在**树莓派**终端运行：

```bash
screen-test touch
```

屏幕会显示5个编号靶点。用手指点靶点，命中应变绿；滑动时应看到轨迹跟随手指。`RESET`清空记录。

```bash
screen-test touch --screen 1
screen-test touch --screen 2
screen-test stop
```

在本工具中，配置`--port`与测试`--screen`统一使用1、2。①号屏对应Linux的`HDMI-A-1`（板子HDMI0），②号屏对应`HDMI-A-2`（板子HDMI1），不按桌面左右位置重新编号。其他系统的“显示器1/2”可能不是同一种编号。

检查的不只是“有没有事件”，还要确认点击哪块实体屏幕就由哪块屏幕响应，触点位置与手指接近。5个靶点命中只验证这些采样位置，不代表所有边缘、多指功能都已验收。

没有安装这个工具时出现`command not found`，表示工具尚未安装，并不表示屏幕损坏。请联系卖家取得适用安装说明。

想在同一模式同时测试颜色与触摸，可运行新版工具的`screen-test tap-cycle`：初始黑色，每次手指按下按白→红→黑切换，不按就不变。每块屏幕独立响应；画面保持纯色，适合观察均匀性和串屏。它不验证精确坐标，坐标与轨迹仍用`screen-test touch`。真实鼠标也可触发切色，请只用手指测试触摸。

## Q4：为什么纯色或网格测试中点击没有变化？

`black`、`white`、`red`、`cycle`、`pattern`用于检查画面，本身不提供点击反馈。请使用`screen-test touch`，或退出测试后操作一个明确支持触摸的应用。

如果界面显示`POINTER / EMULATED TOUCH`，可能是系统把触摸转换成鼠标输入。这不一定是故障；请只用手指操作验证。单凭这类事件无法区分实际鼠标与触摸模拟。

## Q5：连接两块相同型号的屏幕，为什么点击①号却在②号响应？

两个USB触摸控制器可能报告相同的名称或重复/缺失的序列号，系统就可能没有正确区分它们。这属于触摸到显示输出的映射问题，不能单凭串屏判断面板损坏。

先确认两块屏幕各自单独使用时触摸是否正常。随后给两条HDMI线和两条USB数据线贴上A/B标签，逐块接回并测试。把“点击A屏时B屏响应”的现象和接线照片发给卖家。

在部分树莓派环境中，需要按USB物理路径区分两个同名控制器，并分别绑定到对应HDMI。该设置应按本机接线确认，不要复制别人的输入节点或USB路径。

## Q6：连接不同型号、尺寸或分辨率的屏幕，也会串屏吗？

可能会。不同外观的屏幕也可能使用相同触摸芯片，报告相同USB名称。即使名称不同，系统仍需要把每个触摸设备绑定到正确的显示输出。

不同尺寸本身不应作为“不能同时触摸”的结论。需要分别检查每块屏幕的原生分辨率、显示旋转、桌面布局和触摸映射。

先给每块屏幕单独测试，再逐一接回。不要用同一个分辨率或校准参数覆盖所有屏幕；更换屏幕后，如果画面本身不正常，先让主机重新识别新屏幕。

## Q7：为什么点击位置偏移、左右反向或旋转90度？

先确认触摸没有映射到另一块屏幕；再检查系统中的显示方向是否与屏幕安装方向一致。显示画面旋转后，触摸坐标有时还需要单独配置。

如果曾在电脑上留下旧校准或映射设置，请告诉卖家。不要盲目套用网上的校准矩阵，不同系统和显示布局可能需要不同配置。

## Q8：换了USB口、HDMI口或扩展坞后，为什么触摸不对了？

某些多屏配置按USB物理路径和HDMI输出绑定。换口后，主机可能把它视为另一条连接，需要重新识别。

如果此前卖家为多屏做过绑定，请先恢复原来的线缆和接口位置。以后需要长期改变接线时，应重新确认每块屏幕与触摸数据线的对应关系。

## Q9：树莓派SSH能连接，为什么测试程序提示没有桌面会话？

SSH登录与图形桌面登录是两件事。本工具需要树莓派保持图形桌面登录；主动“注销桌面”后，SSH仍能使用，但无法显示测试窗口。

先在树莓派实体屏幕上重新登录桌面。若主机已经配置桌面自动登录，也可以在保存图形应用数据后通过SSH重启显示管理器：

```bash
sudo systemctl restart lightdm
```

这条命令只适用于使用LightDM的对应环境，会关闭图形应用；不适合直接照搬到所有Linux系统。桌面回来后重新运行测试即可。

## Q10：Windows电脑多屏触摸到另一块显示器，如何处理？

先为每块触摸屏连接视频线和USB数据线，暂时使用“扩展”显示模式，以便确认每块屏幕。再到Windows的“Tablet PC Settings / 平板电脑设置”中查找“Setup / 设置”，按屏幕提示识别触摸显示器。[1][2]

如果提示出现在支持触摸的那块屏幕上，按提示点击它；不支持触摸的屏幕如何跳过，请按当前系统界面提示操作。界面位置和可用功能可能随系统版本、驱动及权限不同而变化。[1]

先做屏幕关联，再考虑坐标校准；不要把树莓派的Linux脚本装到Windows上。找不到设置或USB触摸设备时，请把系统版本和设备管理器截图发给卖家。

## Q11：多块屏幕是否能同时多指操作？

“多块屏幕都能分别点击”“一块屏幕支持多点触控”“两块屏幕同时多指操作”是不同能力。是否可用取决于触摸控制器、系统、驱动、输入模式及应用。

本次树莓派验证确认了两块屏幕分别在本屏响应、位置正常，不能据此承诺所有应用的跨屏同时多指功能。若有这种需求，请在购买前向卖家提供主机系统和使用软件，由卖家针对实际场景确认。

## Q12：需要安装触摸驱动吗？

本次测试的USB控制器在已验证树莓派系统中由系统内置驱动识别，不需要额外安装触摸厂商驱动。这个结论不覆盖全部SKU和系统。

显示时序配置、触摸驱动、触摸映射是不同事项。不要将720×720屏幕的显示兼容包当成所有触摸屏的驱动，也不要在系统已识别设备时随意安装其他型号驱动。

## Q13：试过以上步骤仍不正常，需要提供什么？

请提供购买型号、主机和系统版本、屏幕数量、接线照片、单屏是否正常，以及问题属于“完全无触摸”“点到另一块屏幕”“坐标偏移”还是“偶尔断开”。若方便，录一段短视频，同时拍到手指和两块屏幕的反应。

技术支持可能请您提供USB设备列表或短时间触摸事件记录。不要发送Wi-Fi密码、电脑登录密码或SSH密码。
