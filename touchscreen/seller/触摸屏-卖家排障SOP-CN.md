# 触摸屏售后排障 SOP（卖家内部）

版本日期：2026-10-25。面向客服、技术支持和质检。优先适用本项目的HDMI视频＋USB触摸产品，具体SKU额定供电、接口名称、触摸点数和系统支持由产品资料确认。

接口编号统一说明：新版工具的`--port 1`与`--screen 1`对应`HDMI-A-1`（板子HDMI0），`--port 2`与`--screen 2`对应`HDMI-A-2`（板子HDMI1）。配置命令旧版的0/1示例不再适用；保存文件内部键保持兼容，不要手动给JSON重新编号。

## 1. 首次回复：先把问题归类

只问能决定下一步的信息，避免一次要求客户执行大量命令：

| 需确认的信息 | 用途 |
| --- | --- |
| 购买SKU、屏幕数量、主机型号、操作系统与版本 | 判断是否在已支持组合内 |
| 画面是否正常 | 分离显示链路与触摸链路 |
| HDMI和USB两类线各接哪里 | 判断触摸数据是否接到同一主机 |
| 每块屏幕单独使用是否正常 | 区分单设备问题与多屏关联问题 |
| 完全无反应／另一块屏幕响应／偏移／间歇断开 | 决定查USB、映射、校准还是稳定性 |
| 问题前是否换屏、换USB口、换HDMI口、旋转或改系统 | 寻找失效触发条件 |

收集接线照片时，要能看清主机接口、驱动板接口、供电线和USB数据线。允许客户遮住其他无关信息，不需要其登录密码或Wi-Fi密码。

## 2. 按四层判断

| 层级 | 通过标准 | 未通过时的方向 |
| --- | --- | --- |
| A：显示 | 目标屏幕画面稳定，原生模式适用 | 显示时序、接口、线材、供电 |
| B：USB识别 | 系统能识别对应触摸控制器 | 数据线、触摸口、USB口、供电、控制器 |
| C：输入事件 | 实际按下/滑动/抬起产生事件 | 驱动、设备状态、独占读取、硬件触摸链路 |
| D：桌面/应用 | 本屏对应位置产生正确反馈 | 输出映射、鼠标模拟、应用支持、方向、校准 |

不要从“有画面”直接跳到“触摸屏坏了”。USB识别成功也不等于坐标映射正确。

## 3. 单屏有画面、触摸无响应

### A. 无需命令的步骤

1. 核对触摸USB数据口及主机连接，确认不是只接充电器。
2. 用已知支持传数据的USB线，直连主机；暂时移除Hub、延长线、扩展坞。
3. 按SKU说明供电，观察是否有反复掉线、重连或画面同步闪断。
4. 只保留一块触摸屏测试。确认测试应用会反馈点击，不能只观察纯色/网格。
5. 条件允许时，用同一套屏幕和已知好线在另一台已支持主机上做对照。Windows可用只证明那套环境可用，不自动排除Linux驱动或映射问题。

### B. 树莓派只读检查

先核对系统和输入设备，不改配置：

```bash
cat /etc/os-release
uname -r
echo "$XDG_SESSION_TYPE"
loginctl list-sessions
lsusb
cat /proc/bus/input/devices
```

SSH里的`XDG_SESSION_TYPE`可能是tty，不能仅凭它断言实体桌面是X11还是Wayland；结合图形会话和实际桌面进程判断。

若系统已有libinput工具：

```bash
sudo libinput list-devices
```

寻找真实USB触摸设备和`Capabilities: touch`。`Tap-to-click: n/a`是该项设置不适用，不能解释为“触摸屏不支持点击”。

本次样机的名称是`wch.cn USB2IIC_CTP_CONTROL`，VID:PID为`1a86:e5e3`，但其他批次/型号不应据此硬性判断。不相同的ID不等于故障。

### C. 捕获实际触摸事件

从上一步找到本机实际输入节点，把示例`eventN`替换后运行：

```bash
sudo timeout 15s libinput debug-events --device /dev/input/eventN
```

让客户只触摸指定一块屏幕，再看是否出现`TOUCH_DOWN`、`TOUCH_MOTION`、`TOUCH_UP`。不要让客户同时操作两块屏幕，否则无法确认对应关系。超时返回码124通常只是采集时间结束，不等于触摸故障。

注意：若本项目的`pi-setting-touch.service`已运行，它会独占原始控制器输入。这时直接读原始节点可能没有事件，不能据此判定硬件无响应。应读取虚拟设备的节点，或由技术支持先停中转再做原始输入诊断，并在测试后恢复服务。

### D. 输入有事件、界面没反馈

- 确认已登录图形桌面；SSH正常不代表图形桌面仍在。
- 确认当前是交互触摸测试，而不是静态颜色图。
- 检查事件落在哪块屏幕，有无覆盖窗口、锁屏或登录界面。
- 检查labwc的`mouseEmulation`。应用若只监听原生触摸，会漏掉鼠标模拟；本项目新测试模式会分别接收并标记两种输入。
- 不要以`POINTER / EMULATED TOUCH`单独证明多点触控，鼠标模拟路径可能不保留多指语义。

## 4. 多块相同型号触摸屏

### 常见现象

- 点A屏却在B屏响应；两块都控制同一屏。
- 单屏正常，双屏一起用不正常。
- 重启或交换USB口后，原来配对的触摸失效。

### 原因与识别原则

两台设备可能同名、同VID/PID、序列号相同或缺失。名称、VID/PID、EDID型号都不应单独当作每台触摸设备的唯一身份。视频EDID与USB触摸身份也不是同一条链路，无法假设主机会自动配对。

先给每块实体屏幕及HDMI/USB线标A/B。对每块屏幕分别完成：

1. 只保留该屏，确认显示和触摸能工作。
2. 两屏接回后，短时间记录输入，只让客户点A屏，确认对应输入节点。
3. 再只点B屏复核，不直接把剩余设备按出现顺序猜出来。
4. 记录每个控制器的USB物理路径、输出接口、屏幕标签。

记录表（由支持人员填入真实值）：

| 实体标签 | HDMI/Linux输出 | 原始USB设备名 | 序列号 | USB物理路径 | 单屏/双屏结果 |
| --- | --- | --- | --- | --- | --- |
| A |  |  |  |  |  |
| B |  |  |  |  |  |

查询本机实际节点的属性：

```bash
udevadm info --query=property --name=/dev/input/eventN
ls -l /dev/input/by-path/
```

持久绑定可采用经确认的唯一序列号；序列号不可用时，本次采用USB物理路径。`eventN`会变化，不宜直接作为持久身份。Hub或USB插口变更可能改变物理路径，需重新确认。

## 5. 多块不同型号/尺寸/分辨率触摸屏

此类问题不能简单归因于“分辨率不同，不能一起用”。按以下顺序排查：

1. 分别确认每块屏幕画面稳定，读取各自原生显示模式。
2. 分别识别触摸控制器，检查是否其实同名或共用控制器型号。
3. 先用扩展桌面确认各输出，镜像布局另外验证。
4. 确认每个USB触摸设备映射到正确HDMI输出。
5. 再检查该屏独立的显示旋转、缩放和触摸方向。
6. 最后处理仍存在的坐标校准问题，保留原始设置以便回退。

以名称唯一且稳定的设备配置映射，比处理同名设备简单，但仍要通过实际点击验证。不要把一块720×720屏的时序强制给800×800屏，也不要把同一校准矩阵盲目给所有设备。

## 6. 当前树莓派软件的实际解决方案

### 已验证平台

Raspberry Pi 4 Model B、Bookworm Desktop 64位、labwc `0.8.1-1+rpt4`、wlroots `0.18.2-3+rpt3~bpo12+1`。两块同名控制器分别映射后，用户确认两块均在本屏响应且位置正常。

本机曾试用基于`WL_OUTPUT`的udev规则，但该环境下实际串屏未消除，规则已撤回。**不要把那条规则作为已验证修复方案发给客户**。不同软件版本对设备属性支持可能不同，应以实际运行结果为准。

### 最终方案

1. 识别每块屏幕触摸控制器的真实USB路径。
2. 通过可选输入中转为每个控制器建立不同名称的虚拟触摸设备。
3. labwc将不同名称分别映射到HDMI0与HDMI1。
4. 中转原样转发事件，不做坐标变换，并独占原始设备以避免重复输入。

这一方案改变的是主机的软件配置，不写触摸控制器或屏幕固件。不是所有客户必装的“驱动”；已正常的单屏无需安装它。

### 支持人员部署

客户先取得[TEKGROAML Pi Display Tools](https://github.com/tekgroaml/tekgroaml-pi-display-tools)的完整软件包；本触摸屏FAQ目录本身不包含可执行程序。按其中安装文档安装基础工具，之后才进行可选映射。

```bash
sudo apt-get install python3-evdev
cd ~/pi-setting
sudo bash scripts/install.sh --no-deps
```

仅当基础工具依赖已经安装时使用`--no-deps`；首次安装通常按完整安装文档运行，不省略依赖步骤。

下列命令中的`eventN`、`eventM`和用户名都要替换为已确认的当前值；选择原始USB控制器，不要把本项目生成的虚拟设备再次作为输入源：

```bash
sudo python3 scripts/configure-touch-map.py \
  --screen1-device /dev/input/eventN \
  --screen2-device /dev/input/eventM \
  --user YOUR_DESKTOP_USER
```

当前设置程序固定配置两块直触屏；更多屏幕、非直接触摸设备、其他桌面不直接套用。它会检查设备能力、保存USB路径，并备份和追加用户的labwc配置。

配置完毕需重载对应的labwc进程。仅当该桌面用户只有一个labwc进程时，可从该用户SSH终端运行：

```bash
pgrep -u "$(id -u)" -x labwc
```

确认结果只有一个PID后，再执行：

```bash
pkill -HUP -u "$(id -u)" -x labwc
screen-test touch
```

多个会话时由支持人员确认目标PID后重载，不能盲目影响其他桌面会话。

### 检查与回退

```bash
systemctl status pi-setting-touch.service
journalctl -b -u pi-setting-touch.service --no-pager
screen-test status
```

配置位置：`/etc/pi-setting/touch-map.json`；备份目录：`/var/lib/pi-setting/backups`；用户映射：`~/.config/labwc/rc.xml`。

需回退中转时：

```bash
sudo systemctl disable --now pi-setting-touch.service
```

停止会关闭虚拟设备并释放原始控制器。随后可移除用户配置中本程序的两个`PiSetting Touch HDMI`条目并重载，或按完整软件包的卸载说明操作。原有错误的同名映射若仍在，回退后可能恢复原来的串屏现象。

## 7. Windows等其他系统

Windows按系统的显示器关联流程设置，参考客户FAQ中的显示器厂商说明。先确认USB触摸控制器可见，再做屏幕关联，最后才考虑坐标校准。扩展和镜像应分别验证，不直接承诺都支持。

`pi-setting`脚本、labwc配置和Linux服务不适用于Windows。其他Linux桌面、X11和macOS也应按其实际输入体系另行确认，不提供未经验证的通用“免驱、多屏、多点、所有系统兼容”承诺。

## 8. 关闭工单前的验证

至少记录：

- A/B每块屏幕单独工作是否正常。
- 同时连接后，只点A时A反馈、只点B时B反馈，位置接近手指。
- 中心、上下左右采样命中情况与连续滑动轨迹。
- 当前图形桌面与应用输入模式，是否为鼠标模拟。
- HDMI与USB配对位置，是否需要固定插口。
- 重新登录、重启后的映射是否恢复；若未测试，明确记录“未验证”。

质检若要宣传更广能力，还需单独验证冷启动、睡眠唤醒、热拔插、屏幕旋转、跨屏多指并发、不同屏幕组合及其他系统版本。不要把功能未验收写成已通过。

## 9. 何时转硬件或退换流程

如果使用已知好的数据线、正确接口和供电，在产品明确支持的另一台主机上也无法识别或稳定产生触摸事件，且对照设备可用，可将复现证据转交硬件支持，并按卖家的售后流程处理。

如果两块单独都正常、一起才串屏，优先转映射支持。避免让客户为已经能采集到正常触摸事件的设备重复购买线材或反复刷系统。
